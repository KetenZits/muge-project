## Performance evidence

Browser measurements used a warm local Next.js development server, headless Chrome, reduced motion, 1440×900, and three reloads per route. Times are medians from navigation to the first rendered result, include automation overhead, and are not production Core Web Vitals:

- Home: 972→917 document elements; 16→16 initial articles; 412→392 ms median reload-to-results.
- Discover: 1,257→805 document elements (36% fewer); 23→12 initial previews, with all results still reachable; 462→380 ms median reload-to-results.
- Team Finder: 942→741 document elements (21% fewer); 15→15 initial articles; 401→395 ms median reload-to-results. The small timing difference is not evidence of a material speedup.
- Node filter-and-sort benchmark, seven rounds: 15 seeded teams, 0.0490→0.0153 ms per call; 1,500 synthetic teams, 11.6062→1.4817 ms. The synthetic case is not browser interaction latency.

Changes behind these results: bounded initial result lists with continuation, narrower Zustand subscriptions and per-item booleans, cached scores within each sort, lookup maps, indexed single-post comment lookup, linear comment aggregation, deduplicated local/seed merges, and composer/search code split until opened. The existing bulk image reads, lazy image decoding, size limits, and ref-counted object URL lifecycle were retained and regression tested. No blanket React.memo/useMemo rollout or speculative index/schema changes were made.

Cached script transferSize values in the raw browser logs are diagnostic only; they are not an initial bundle-size comparison. Large optional 3D dependencies remain isolated to the existing lazy landing scene. Production LCP, INP, CLS, network transfer, and physical-device performance were not benchmarked.

Raw measurements: [browser before](performance-before.json), [browser after](performance-after.json), [filter before](discovery-before.json), [filter after](discovery-after.json).

## Remaining limits

Interactive CUA browser control was unavailable; validation used headless Chrome and code inspection. Physical devices, real mobile keyboards, Safari/Firefox, screen-reader output, and real browser zoom were not verified. Browser Back/Forward and contextual return URLs preserve filters; exact scroll restoration follows browser/Next.js behavior. Real user delivery and cross-device synchronization remain outside this frontend-only prototype.
